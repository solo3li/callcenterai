# تنفيذ الثلاثية المتفق عليها: Gemini Live + Transcript حي + Gemini Embeddings

الهدف: تحويل خط المكالمات من pipeline فارغ إلى مكالمة AI حقيقية، وتوحيد مزوّد الذكاء الاصطناعي على Google (Live API للمكالمات، Gemini للتفريغ، gemini-embedding-001 للـ RAG). مع الإصلاحات الربطية الضرورية لعمل الثلاثية فقط — بدون التوسع لباقي الفجوات.

## 1) ai_service/main.py — Gemini Live حقيقي في الـ Pipeline
- استبدال `GoogleLLMService` (المستخدم غير الموصول) بـ `GeminiLiveLLMService` من pipecat، وتثبيت النسخة في `ai_service/requirements.txt` (`pipecat-ai[livekit,google]` بنسخة محددة تدعم Gemini Live — يُتحقق من مسار الـ import الفعلي عند التنفيذ من الحزمة المثبتة).
- بناء الـ pipeline الصحيح: `Pipeline([transport.input(), gemini_live, transport.output()])` بدلاً من input→output المباشر.
- التهيئة من الـ Redis payload الموجود: `voice` و`language` من `AIAgent`، `temperature`، `system_instruction = full_prompt` (بما فيه تعليمات أدوات RAG)، و`model` عبر env `GEMINI_LIVE_MODEL` بقيمة افتراضية حالية.
- الأدوات: بناء `function_declarations` حقيقية لـ Gemini من `input_schema` الـ actions الديناميكية (إصلاح التعليق "المزيف" في سطر 138) + أداة `search_company_knowledge`، وتسجيل الـ callbacks بنفس نمط `register_function` الحالي.
- التقاط transcript حي: processor صغير داخل الـ pipeline يجمع TranscriptionFrame (المتصل) وTextFrame (رد الـ AI) في قائمة — بدل الـ "transcript" الوهمي الحالي (نسخة الـ system prompt).
- إصلاح URL الحفظ: `/api/analytics/save-transcript/` → `/analytics/api/save-transcript/`، وبعد انتهاء `runner.run` يُرسل transcript المجمّع بنفس شكل `save_transcript` (room_name, transcript, agent_id) ثم يُشغَّل تحليل Gemini بعدها تلقائياً كما هو.
- إضافة `GEMINI_API_KEY` إلى environment الخاصة بـ ai_worker في `ai_service/docker-compose.yml`.

## 2) core — مفتاح الإجراءات المكسور (شرط لعمل أدوات الـ AI)
- إضافة `INTERNAL_API_KEY = os.environ.get('INTERNAL_API_KEY', 'my_secure_internal_key')` إلى `project_service_main/core/callcenter_project/settings.py` (قرب سطر 125) — بدونه endpoints قائمة/تنفيذ الإجراءات ترمي AttributeError 500، والأدوات الديناميكية في Gemini Live لن تعمل أصلاً.
- إضافة `GEMINI_API_KEY` لنفس الملف (للتفريغ في البند 4).

## 3) rag_service — Gemini embeddings بدل OpenAI
- `rag_service/requirements.txt`: إزالة `openai==1.14.0`، إضافة `google-genai`.
- `rag_service/rag_core/settings.py`: استبدال `OPENAI_API_KEY` بـ `GEMINI_API_KEY`.
- `rag_service/knowledge/services.py`:
  - دالة مساعدة موحدة للـ embeddings عبر `google.genai` بموديل `gemini-embedding-001` و`output_dimensionality=1536` (للحفاظ على `VectorField(dimensions=1536)` في pgvector بدون أي migration).
  - `process_document`: تضمين الـ chunks بـ `task_type="RETRIEVAL_DOCUMENT"` (مع batching دفعات بدل استدعاء لكل chunk).
  - `retrieve_relevant_chunks`: تضمين الاستعلام بـ `task_type="RETRIEVAL_QUERY"` بنفس الموديل والأبعاد — هذه النقطة الحرجة لجودة الاسترجاع.
- أمر إعادة تضمين: management command جديد `knowledge/management/commands/reembed_all.py` في rag_service يمسح الـ chunks القديمة (المبنية على OpenAI — غير متوافقة رياضياً) ويعيد معالجة كل المستندات. البيانات الحالية demo فالإعادة رخيصة.

## 4) core — تفريغ تسجيلات المكالمات البشرية بـ Gemini
- `project_service_main/core/analytics/transcription_workflow.py`: استبدال Whisper بـ google-genai (Files API للصوت + `generate_content` بموديل flash وprompt يطلب transcript بطوابع زمنية وتمييز المتحدثين) — بدون خطوة ffmpeg (Gemini ياخذ mp4 مباشرة عبر Files API).
- تخفيف شرط الـ isolated tracks: لو غير موجودة (حالة egress الخاص بالحملات الذي ينتج composite فقط) يستخدم الملف الموحد ويطلب من Gemini تمييز الأدوار — بدل الإرجاع "skipped" الحالي.
- تسجيل الـ workflow المعطّل: في `project_service_main/core/analytics/urls.py` إضافة `process_recording_workflow` إلى قائمة `serve(inngest_client, [...])` — حالياً الحدث `analytics/process_recording` يُرسل من مكانين ولا أحد يستقبله.
- `project_service_main/core/requirements.txt`: إضافة `google-genai` (موجود فعلاً في الـ venv نسخة 2.22.0 بشكل عرضي — نثبته صراحة).

## ما لا يشمله النطاق (باقي الحلقات المقطوعة الست الأخرى)
SIP provisioning في LiveKit، bug `provider_id` في الحملات، إنهاء المكالمة/EndFrame، إصلاحات agent_app، وحدة audit، الاختبارات — كلها خارج هذا التنفيذ ما لم تطلبها.

## التحقق بعد التنفيذ
- `python -m py_compile` على الملفات المعدلة الثلاث خدمات، و`manage.py check` لـ core وrag_service.
- فحص أن مسار import الـ Gemini Live service في pipecat صحيح ضد النسخة المثبتة في الحاوية (docker build ثم فحص الحزمة) — الـ import الحالي `pipecat.models.google` يبدو خاطئاً لكل النسخ فسيُصحح حسب الموجود.
- اختبار تشغيلي حقيقي للمكالمة يتطلب LiveKit + مفتاح Gemini فاعل — سأوثق خطوات التشغيل المطلوبة عندك بدل ادعاء اختبار غير ممكن هنا.
